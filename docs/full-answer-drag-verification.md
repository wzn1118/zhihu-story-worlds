# 直接拖动获取回答全文

2026-09-14 发布 `full-answer-drag-20260914`，基于 `answer-capture-20260914` 合并本轮修改。

公网用户无需先手动展开回答：原网页拖动、搜索结果卡片、问题列表中的回答均先进入全文获取流程，取得真实正文后才保存。UI 显示“正在获取回答全文…”及后续保存阶段。搜索/问题接口仅提供的摘要仍用于列表预览，不会在拖入时直接冒充全文。

原网页优先自动点击该回答的原生展开控件，等待真实正文完成；缺少展开控件或只有摘要时，后台访问服务端已验证的准确回答详情，复用该账号自己的浏览器会话。后台读取不会替换前台 URL、滚动、历史及控件 ID；原生链接展开、派生详情标签页及前台延迟弹窗分别处理。回答正文排除作者简介，保留原段落。完成后更新书袋和页面，同一回答不重复计数。

候选 ID 在当前账号目录校验后才分配浏览器，已保存的展开正文直接复用。获取不到正文、知乎要求登录/验证、返回 403、只给摘要、出现其他回答时均不将摘要保存为全文。知乎登录或访问权限要求仍需由用户在官方页面完成，系统不绕过这些限制。

验证：20 项原网页回归通过；最终候选全文测试 10 项通过；发布候选服务、DOM、账号及 OAuth 回归 48 项通过；电脑/手机 UI 共 12 场景通过；生产 TypeScript 与 Vite 构建通过。测试包含延迟控件、同 URL 的原生展开链接、后台详情子标签页、前台延迟弹窗保留、来源隔离及失败不入袋。

验证边界：使用真实 Chromium、真实 React 与实际服务及存储；知乎远端页面/部分响应使用隔离夹具，没有使用用户 Cookie，也没有声称已实测用户账号下任意回答。

使用方式：刷新公网应用后，直接把尚未展开的回答拖给刘看山，等待获取正文完成。

公网验收：健康标记为本版本，首页和工作台模块与构建文件逐字一致，新全文接口匿名访问返回 401，源站 OAuth 与资源检查通过。
