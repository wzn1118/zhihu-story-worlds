## 运行与故障状态

`npm run stories -- list` 与 `npm run stories -- get <id>` 调用项目自带的 `scripts/story-cli.mjs`。这是本项目适配器，不是官方 `zhihu-cli` 提供的子命令。它使用同一服务类，直接访问文档指定的固定 HTTPS 主机，不执行 shell 命令、不读取鉴权信息、不自动重试。

服务端有 12 秒超时、4 MiB 响应上限、严格数字 ID 校验与列表存在性检查。禁止跟随 HTTP 跳转。成功响应缓存 5 分钟；到期尝试实时读取一次，失败时有缓存就显式返回 `source: cache` 与警告，没有缓存就返回结构化错误。客户端可通过 `?refresh=1` 请求重新获取一次。缓存写入失败不会伪装为网络失败。

`GET /api/stories` 返回 `{ stories, source, fetchedAt, warning? }`。
`GET /api/stories/:id` 返回实际详情与同样的来源状态。
`GET /api/worlds/:id` 返回编译后的 Ink 叙事和结构化场景；其余真实故事返回 409 `WORLD_NOT_PREPARED`，仍可读取来源。

Ink 2.x 是唯一执行分支与变量更新的叙事引擎。结构化图提供显示元数据；它被编译成 Ink，线索条件、决心和信任更新均由 Ink 执行。前端可保存 `Story.state.ToJson()` 并恢复完整分支状态。首三部世界均有至少 12 个场景和 3 个可达结局；新增未来岛为 22 个场景、4 个结局。未来岛的线索库存记录已经预留或投入的配额与交接，不假装它是实时数值库存。净水公约、联合航线与完整证词，分别要求在前置选择中实际取得对应资源或核查记录。
