# Catalog A 选择后果审读

日期：2026-09-06。修改文件：`content/catalog-a.ts`。本次检查八个世界的公共场景、选择门槛、资源变化和结局承接，先修正三组直接矛盾，再按续修要求处理下文列出的其余叙事与资源说明问题。当前默认是这份文件的续修版本。另读取 `docs/catalog-a-source-review.md`，并复核 `.local/zhihu-cache/story-1986486345988851330.json` 的真实节选；原文缓存未修改。

## 本次修正

### 1. 大明篇：互斥的粮食行动被写成同时完成

`ming-whisper.dispatch` 的 `sign_transport`、`sign_relief`、`hold_dispatch` 是互斥选择，但原 `receipt` 同时叙述援军车队回报与城门赈济签收。选择暂缓也会看到已经交付的粮。另有两处同类问题：`keep_record` 无条件可选，因而已援运的玩家也会进入“车没有出发、援助没完成”的结局；`ending_relief` 强制称姐姐饰物已兑粮，实际可选择 `protect_queen` 保留饰物。

已将公共 `receipt` 改为核对已办、待办文书，保留未签收空格；`ending_record` 如实登记已发生支出与未落实请求；`ending_relief` 只确认有门槛保证的实际发粮，不指定未必发生的筹粮来源。援运、赈济结局仍由原线索门槛保证。

### 2. 秋收篇：未付粮做饭仍被叙述为吃完十碗

`harvest-box.open_box` 中只有 `offer_meal` 扣一份存粮，`ask_seal`、`set_house_rules` 都不扣粮，但三个选择原先都会进入“第十碗之后”，并看到沈凶已经喝完面汤。这会让付粮选择看起来没有代价之外的差别，也与库存展示冲突。

已将公共场景改为“锅底与明早”：到灶边讨论身体情况与粮食预算，已取用和未动用的粮分别记清，不替未做饭的玩家宣布吃完。后续 `portion_food` 的一份粮成本与原有选择文字均保留。

原节选确实写了十碗鸡蛋面，但原文中的既成情节不能直接套在游戏的互斥行动之后。此处改变的是原创游戏分支承接，原文读者仍看到缓存中的真实文字。

### 3. 秋收篇：未寄信收到回信，未索赔结局却收到赔偿

`letter_return` 对所有路线开放，玩家可以完全不取得 `询问信件`，原场景仍宣称递信者“带回答复”。场景又预设损坏已有记录，而实际 `yard` 可以只清点存粮或先开箱。最后，`ending_coop` 仅要求 `互助约定`，原文案却强制写李仙昀已经赔付院墙。

已将来信改为送箱者主动派人核查的来信，因此寄信与未寄信两类路线都能接上。询问信件仍是可记录的额外行动。公共场景只让玩家出示手边凭据，不预设损坏清单齐全；来人明确可以把现场核实的材料折粮交付，为 `claim_repairs` 当下的 `food +2` 提供因果。独居互助结局只区分实收与未了事项，不再发放未获得的赔偿。

这些来信、折粮细节属于已声明的原创改编，不是原节选的新增事实。
