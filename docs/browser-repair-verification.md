# 内置知乎浏览器修复验收（2026-09-14）

## 根因

线上 `context.route` 在知乎新窗口的初始导航上直接调用 `request.frame()`。Playwright 在这一阶段可能还没有 Frame，未捕获异常使整个 Node 服务退出。旧客户端继续显示之前的登录截图，后续操作因此返回 `BROWSER_CLOSED`。日志确认服务发生过连续重启。

原截图界面也缺少登录状态自动刷新、直接键盘输入、触摸滚动与验证码拖动，重新连接未完整处理旧画面与排队操作。

## 修复

- 导航拦截与响应事件处理无 Frame 情况、页面关闭竞态，所有顶层导航仍验证 HTTPS 知乎域名。
- 合法知乎弹窗可操作，后退可返回原窗口；异常关闭后释放占用并恢复同账号的持久浏览目录。
- 登录和验证使用实时截图；二维码后台单次轮询，不禁用操作按钮。阅读页面继续支持选字、原回答列表和拖给刘看山。
- 截图支持直接键盘、粘贴、中文输入、手机输入焦点、纵向触摸滚动和横向滑块拖动。只返回输入框类型与位置，不返回密码或输入值。
- 重连清除旧画面，丢弃旧连接排队操作，不重复发送登录提交或验证码请求。请求超时后可恢复操作。
- 账号之间隔离窗口、Cookie 和选篇；浏览器关闭保留同账号的持久 Cookie。

## 验证方式与边界

62 项针对性后端、OAuth、账号、DOM 与请求恢复测试通过。真实 Chromium 回归确实触发无 Frame 新窗口导航，覆盖导致服务崩溃的路径，并验证 Cookie 持久化、验证码覆盖层和弹窗返回。

14 项前端交互场景在桌面和触摸浏览器通过，含中文输入、缩放、手机纵向滚动、横向拖动、单次后台请求、断线恢复、不重放提交和代理错误清理。

真实网络集成使用实际 React 界面、实际账号浏览器服务与 `www.zhihu.com` 页面，在临时测试身份和独立临时目录运行。检查二维码加载、短信/密码切换、虚构文本输入与清空、刷新后点击、重连、触屏、Cookie 持久化与第二账号隔离。测试不发送短信、不填写真实密码，不提交登录或替用户确认授权，因此不宣称已完成真实用户账号的最后登录确认。

发布基于当时最新线上版本，保留其他任务已上线的收藏、创作配置和美术加载修改。最终发布信息及机器检查结果见同目录 JSON 报告。
