# 热榜链接跳转与知乎访问限制（2026-09-14）

用户报告从热榜进入具体问题时收到知乎 HTTP 403，页面 JSON 错误码为 `40362`。这与此前内置浏览器导航异常导致服务崩溃是两类问题。

现有实现将克隆页面上的链接强制改成 `page.goto`，包括原本在新窗口打开的链接。这跳过真实网站的点击处理、客户端路由和浏览器自然产生的来源信息。本次恢复真实页面中对应链接的原生点击；地址栏输入网址仍使用导航。链接节点已被网站替换时，通过相同的完整 HTTPS 知乎网址寻找当前真实节点，不在链接不存在时盲目重新请求。站点自身的 `noreferrer` 策略保持有效，没有注入来源请求头、伪装浏览器指纹或迁移他人的登录 Cookie。

单独识别拒绝访问与可交互安全验证页面。40362 JSON 页面停止后台重复截图刷新，提供返回上一页、返回热榜、在用户自己的浏览器打开原页；没有验证控件时不再提示用户在空白错误页面登录。`/account/unhuman` 等真实验证页面保留动态刷新和输入、拖动能力。

回归通过真实 Chromium 驱动、本地受控网页响应，验证点击处理、来源信息、站内路由、回收节点、新窗口、拒绝访问状态及验证页。这证明应用导航行为得到修复，不代表知乎对真实账号的限制已经解除。

真实匿名网络检查中，`https://www.zhihu.com/hot` 返回 403，随后知乎重定向至 `/account/unhuman` 并返回 200 安全验证页。该页没有问题链接，未进一步请求问题页。未读取用户持久 Cookie、未提交登录或自动完成验证。因此当前已登录用户再次进入热榜具体问题是否成功，仍需本人重试确认。

验证记录：`output/hotlist-live-diagnostic.json`、`output/hotlist-ui-regression.json`。最终部署与测试状态见同目录 JSON 报告。

发布结果：`releases/hotlist-navigation-20260914` 已上线；30 项针对性测试、10 项 UI 场景通过，公网首页与构建包一致，健康与源站权限检查通过。发布后服务 active，自动重启次数为 0。
