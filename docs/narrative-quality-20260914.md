# 故事生成：人物利害与分支连续性

本次针对新生成游戏的代入感、文字模板感与分支串线；不批量改写用户已经发布的游戏。

## 根因与实现

快速模式原提示要求每场45–70字、统一动作或声音开头，却把较多字数给了说明和反馈；还固定使用带阁楼、车站、舞台含义的节点名，并同时要求12场3结局和只有最后2节点为结局。真实线上稿件中出现了题材迁移、相同装饰细节、明显一好一坏的选项，甚至在无法获得提词卡的支路里默认玩家已经持有它。

新快速模式仍一次输出完整稿。输出最前面的内部 narrative 记录主角原本的小目标、私人损失、与配角的关系和各自说话方式，再写场景。正文贴近玩家感知，每场围绕一次有阻力的行动，保留人物回避、催促和讨价还价；不要求统一句法，不替玩家总结情绪。节点编号改为中性 s0–s8/e0–e2，统一9场决策和3个结局。正文目标80–140字，缩短介绍、提示与反馈以平衡总输出。

每场及结局的内部 requires 声明其默认玩家已取得的物品、消息、获救状态或承诺。程序从 start 沿无环图计算所有入边路径已获得 gains 的交集；只在某条支路成立的前提不能出现在共用场景中。校验失败进入既有的一次修复额度，不增加独立润色或审稿请求。requires 不作为隐藏选项门槛，也不展示给玩家。

完整模式在现有大纲字段写入人物私心、旧关系与事件因果；逐场写作加入真实入边的动作、反馈、条件与消耗，以及最近两场相关原文，总原文预算1800字。已生成场景不等于玩家都经历过。并发前驱尚未完成时标明未知，汇合场景仅承接共有事实。

针对快速生成、完整路线、文本兼容、编译、审稿、结构修复及relay的76项测试通过；随后新增缓存失败链路测试，快速模式16项通过；生产TypeScript及前端构建通过。快速模式测试覆盖分支独有线索、同目标不同选项、当前选择无法满足事前知识、结局前提、内部笔记不泄露、旧稿可编译、修复次数与超时、旧提示缓存失效、全部路径和存档往返。既有fast测试夹具同时修正了重复选项、未实际出场的角色以及已过时的14k输出上限断言；修改前10项中4项已失败。

真实模型对照记录保存在 output/narrative-quality/latest.json 所指的目录；输入为工作台原创种子《第七秒的来电》，忠实改编，两版本同模型、low、10k上限、并行请求，结果不进入用户书库、不触发配图。

部署基于实时活动release，仅覆盖此次6个源文件和测试文件，保留其账号隔离、个人中转配置、前端交付文件及共享存储。发布状态与回滚记录见 output/narrative-quality 的manifest和部署记录。

## 真实模型验证结果与限制

首次并行对照：旧版180.95秒首轮成功；新版161.6秒时流连接中断、唯一重试在总284.5秒处超时，没有完整新稿，不计作质量通过。随后单独新版非流式请求145.25秒成功，12场/9决策/3结局/16路径；普通场景正文1074字，旧样本496字；输出4665 tokens，旧样本5193。样本与传输方式差异使这组记录不能证明稳定提速。

新稿恢复原主角陆遥，以押金回执、补签旧事故记录及艇长被连累停航建立人物利害；角色有不同要求和讨价还价，6个非空requires全部有共同入边证据。人工审读仍发现艇长未计入人数、所有结局未充分兑现谜底。这些问题已补入最终提示：在既有premise.preserved中核对包括命名人物在内的总数/时间/设备事实，premise.expansion先定隐藏原因和证据，至少一个结局以证据揭示小说谜因。此最终提示微调未另调用模型；它是约束加强，不宣称自然语言一致性已有程序级保证。
