# 回答正文捕获与拖动一致性修复

2026-09-14 已发布 `answer-capture-20260914`，基于当前线上 `narrative-quality-final-20260914` 合入本次修复，保留现有作品生成等功能。

根因是作者简介和回答正文同时使用 `.RichText`，旧的联合选择器按 DOM 顺序取到了前面的简介。因此页面中已展开的长回答会错误显示为 4 字或 13 字。本次只在回答正文容器中取文，排除个人资料；正文中存在多个 RichText 区块或引用时保留开头、中间和结尾全部段落。

折叠回答拖入时，服务端按准确回答来源定位原页面，只点击该回答的原生展开控件，等待文本更新并稳定后保存。异步展开失败或目标已离开页面时返回明确错误，不把尚未展开的摘要保存成正文。已展开的回答继续使用拖动时选定的服务端快照。

书袋按回答 ID 合并展示，完整展开版本优先，较短的旧节选不会覆盖已展开正文；同一问题的不同回答保持独立。旧内容记录不删除、不改写，历史引用仍可读取。捕获完成后同步刷新内置页面，初次加载书袋的较晚响应不能覆盖刚刚拖入的结果。

验证：74 项服务测试通过；发布候选内 12 项浏览器测试通过；电脑、手机均通过真实鼠标或触摸拖动，验证折叠 77 字自动展开为 166 字、手动展开后仍为相同 166 字且仅计一篇、另一个回答计为第二篇、刷新后保持正确。TypeScript、Vite 构建、源站部署检查通过。公网健康发布标记、首页静态文件和知乎工作台模块逐字匹配构建产物。

测试使用真实 Chromium、真实 React 页面及捕获和书袋持久化代码，知乎页面内容和部分浏览器响应为隔离夹具。未使用真实用户 Cookie，未实测截图所示账号的那一条回答。

使用方式：刷新公网应用，重新打开回答后拖入。此前只有作者简介且没有正文版本的旧记录，需要重新拖入一次才会得到当前页面正文。
