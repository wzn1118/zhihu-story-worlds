# 公网 OAuth 与多用户知乎浏览器验收

当前发布目录：`releases/oauth-multiuser-20260914`。

App 580 的平台注册回调原仍为 `http://127.0.0.1`，确认授权接口返回 `Invalid Redirect URI`。已使用赛事页的保存操作更正为 `https://zhihu.hegelsalon.com/auth/callback`，重读平台数据确认生效；发布前后均在服务日志确认完整 OAuth 登录成功。

公网恢复“知乎网页”与“知乎内容阅读”，保留网页选字、回答拖放和“交给看山”。每个认证账号独立保存 Chromium Cookie、浏览器状态、发现内容、书袋、手记、记忆、作品和浏览器存档；请求携带预期账号标识，服务端拒绝跨标签换号后的旧请求。配置服务由管理员管理。

OAuth 登录只建立赤页身份；知乎网站浏览器首次仍需本人在内置页面登录。真实联网测试确认两个独立窗口均以 HTTP 200 打开知乎登录页面、Cookie 隔离；没有代用户登录，也没有把测试正文当作线上知乎内容。

候选发布构建及 54 项测试通过。桌面与手机浏览器验证内置页面、拖放、按钮喂文；另有 10 项浏览器账号切换场景通过。生产配置下 Chromium 启动和真实知乎登录页返回均已检查，公网 `/api/auth/me` 返回 `browserAvailable=true`。刘看山使用现有服务配置的一次真实聊天调用已成功。

共享 CLI 的账号私有能力不会作为访客账号使用。当前未配置 Access Secret，对应搜索和收藏列表能力仍未开通。独立浏览器默认最多同时 4 个，闲置 10 分钟关闭，账号 Cookie 保留在各自 0700 目录；重开可复用该账号的浏览状态。

工作区同时存在其他任务对模型选择、收藏和产品介绍的修改。本发布保留已验证的 OAuth 实现，并在独立发布目录隔离这些并行修改；根工作区文件未回退。
