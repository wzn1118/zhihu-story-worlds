# 赤页 RED LEAF：整体产品说明

[返回项目首页](../README.md)

赤页是一款基于知乎内容的阅读与互动创作工作台。它将真实来源、阅读理解、互动改编、游玩与记录放在同一套产品流程中，让读者可以在理解原文的基础上继续参与和创作。

## 产品全景

蓝白色工作台由故事书库、新故事工作台、我的存档和结局档案构成。作品卡片同时展示标题、题材、作者、改编状态以及“读原作”“玩改编”入口，刘看山陪伴入口保留在工作区。

![赤页蓝白故事书库与整体产品导航](readme-assets/product-library.webp)

| 入口 | 用户目标 | 主要能力 |
| --- | --- | --- |
| 知乎故事书库 | 找到想读、想玩或想继续创作的内容 | 浏览、题材筛选、搜索、收藏、原作与改编入口 |
| 知乎内容阅读 | 回到原文，理解作者和具体语境 | 保留标题、作者、原文链接、节选与来源信息 |
| 刘看山陪伴 | 把零散信息整理为可继续使用的理解 | 摘要、人物、关系、时间线、动机、线索与阅读手记 |
| 新故事工作台 | 将阅读所得变成互动创作 | 导入原文、改编方向、人物、场景、对白、选择、结局与配图 |
| 我的存档 | 随时恢复体验 | 自动存档、手动备份、导入导出 |
| 结局档案 | 比较与复盘不同路线 | 结局记录、路线回看、回溯与复玩 |

## 真实来源与阅读

赤页从真实知乎内容出发。每个故事保留原作标题、作者和来源链接，用户可以查看原文节选，并在创作与游玩过程中回到原作依据。

![从知乎原文中选取内容](readme-assets/product-source-selection.webp)

内容改编保留原作的核心问题、人物关系与情绪张力，并新增玩家身份、目标、有限资源、选择节点与可比较的结局。互动对白、分支、结局和视觉表现标明为改编，不替代原作完整内容，也不代表原作者的原文结论。

上游服务不可用时，产品显示缓存或错误状态，同时保留来源与获取时间。

## 刘看山与阅读手记

刘看山将理解内容的过程留在工作台中。读者可以梳理摘要、人物关系、时间线、动机与线索，标记还不能确认的信息，再带着问题回到原文。

这些信息也为创作提供起点：人物为什么行动、矛盾发生在什么地方、哪些线索会改变判断，都可以继续转化为场景、选择与后果。

## 从回答到互动故事

新故事工作台集中呈现知乎内容入口、原文导入、创作任务与项目列表。用户可以选择“灵感改编”或“沿原作扩展”，逐步设计人物、场景、分支、结局和美术。

![蓝白版新故事工作台](readme-assets/product-workshop.webp)

```mermaid
flowchart LR
    A[选择知乎内容] --> B[查看原作与来源]
    B --> C[整理阅读手记]
    C --> D[设计互动改编]
    D --> E[生成与检查]
    E --> F[进入故事]
    F --> G[保存 回溯 再创作]
```

生成过程展示构思剧情、写作场景、检查分支等阶段，以及对应的制作日志。原文入口随任务保留，方便用户在制作过程中继续核对内容。

![故事制作阶段与生成日志](readme-assets/product-generation.webp)

用户可以按需要选择纯文字、简单插图或精细配图的创作方式；制作完成后进入故事，通过实际选择检验场景、对白和路线是否成立。

## 互动体验与记录

每个故事世界围绕身份、目标、地点、人物、资源、线索和结局展开。阅读与观察带来信息，行动消耗机会或物资，选择改变关系和后续路线，结果成为下一次判断的依据。

- **保存与恢复：** 自动保存当前进度，支持手动备份和导入导出。
- **回看与回溯：** 回顾已经发生的剧情，返回更早的选择。
- **结局记录：** 保留路线结果，支持复玩与比较。
- **持续创作：** 将阅读与游玩过程中产生的新想法带回工作台。

书库包含《蓝血》《同时被两个精神病追杀》《史密斯装穷夫妇》《末世我靠钞能力躺赢》等作品。《重生周》是其中一个互动改编案例，展示时间、信息、资源与关系如何共同影响剧情。

## 面向谁

| 用户 | 产品价值 |
| --- | --- |
| 知乎读者 | 从阅读进入判断，在选择与回溯中进一步理解内容 |
| 故事作者 | 将现有内容扩展为可以编辑、游玩和继续创作的分支 |
| 知识型创作者 | 通过具体处境与模拟决策表达方法、经验和因果关系 |
| 社区参与者 | 围绕具体线索、选择与结局展开讨论与二次创作 |

## 技术实现与继续建设

前端使用 React、TypeScript 与 Vite；服务端使用 Node.js 与 Express。分支叙事由 InkJS 及故事状态管理驱动，资源、线索、关系与条件参与后续剧情。独立游戏运行时通过受限消息通道与主工作台同步状态。

美术原文件通过 Git LFS 保存，公开资源目录与 SHA-256 清单随仓库发布。账号、浏览器会话、密钥与个人工坊数据保留在本机私有目录。

项目继续完善角色与场景美术、来源段落到剧情节点的映射，以及创作者编辑、审核和发布流程。后续方向包括共创模板、分支投稿、反馈与结局数据面板和更多内容题材。
