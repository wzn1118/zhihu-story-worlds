# 全游戏美术加载逻辑优化

已于 2026-09-14T12:01:34.647389+00:00 发布到公网，无需重启服务。

本轮只修改请求调度、可见性、预取、取消、解码复用和清单获取。没有修改任何游戏图片文件、尺寸或画质。

## 覆盖范围与逻辑

20款内置游戏、生成/导入游戏共用 Artwork 和同一个请求调度器，涵盖书库封面、场景背景、人物、结局、人物资料、工作台审核图。重生周的背景、人物、序章、道具、教程、UI、画廊、结局接入该游戏内部同一调度器。

- 严格优先：当前场景/人物或书库主图完成下载和解码后，才允许普通可见图片占用带宽；可见图完成后才启动最多一个推测请求。弱网降低并发，省流/极慢网不预取。
- 真正延迟加载：IntersectionObserver 判断现有图片框是否可见，未进视口、关闭的详情、被弹窗遮住的书库不提前下载。
- 去重与取消：URL统一化后共享请求；多个消费者只发一次；只有最后消费者离开才取消。React换节点/预取交接使用微任务，避免同URL旧组件卸载造成下载重启。
- 同源图片用 AbortController 真正取消请求，下载后共享 blob URL，展示私有 no-store 图也不会多下载一次。跨域原作封面兼容无CORS的Image加载。
- 公共图片保留解码结果，按LRU和设备内存设置12–32MiB、48项缓存预算。正在显示的图片不强制逐出；已完成公共预取立即释放固定占用，让LRU生效。私有图片只保留在活跃订阅内，账号变化清除任务与缓存。
- 只预取下一次人物变化、玩家指向的选项、唯一后续节点及开场图片；最多3个候选。不执行Ink选择或改动存档。
- 大图仍有数据传输时不会被30秒总超时误杀；同源超时判断的是连续30秒无新数据。
- 两份公开美术清单并行读取，跨游戏合并在途请求。后续读取每次向服务器验证，304复用已解析数据。HEAD发现新版本时取消旧读取。审核规则、SHA绑定与私有资源鉴权保持原逻辑。

## 验证与测量

- 20游戏、838场景、2168段文本的选图/预取测试；明确验证下一人物、指定分支、暂缓美术、导入游戏以及游戏状态未推进。
- 20款内置游戏 + 1个导入游戏浏览器验证通过，JS错误为0。有发布来源的开场背景/人物均加载成功。hollow-immortals、wrong-realm开场当时无发布来源，仍按既有规则留空。
- 12项真实React/HTTP浏览器回归覆盖同图换组件、预取交接、滚动、关闭details、请求取消、失败回退、私有图只下载一次。
- 17项共享调度器、8项清单、25项全世界选图、14项实时美术、4项场景/人物原有测试通过。重生周23项调度及7项浏览器回归通过。
- 使用同一套原图，冷缓存、1.6Mbps、120ms、1440×960：重生周从首次图片请求到背景与人物同时就绪，三轮中位数 **1672ms → 837ms**；此阶段图片请求 **8 → 3**。这是本地限速对照，不能当作所有游戏或任意公网网络的固定倍数。
- 书库前一阶段对照首张封面就绪前图片请求中位数30→4；端到端35.98→35.79秒基本持平，包含脚本、远程字体和封面原始字节传输。之后进一步改成严格主图优先。此记录用于区分减少无用请求与整体启动速度，不宣称全站翻倍。

发布后已核对公网首页、两套JS文件的SHA与健康检查；实际运行服务上的背景加载和账号入口检查通过。公网HTTP与本地运行服务浏览器验证的范围分别记录在 `public-verification.json`。

证据在 `output/site-art-loading/` 和 `output/redrain-loading-stage/`。发布记录包含准确部署目录、备份目录、文件SHA及零图片文件修改；仅更新前端文件与重生周静态代码，无需重启服务。
